## 3. KAARSHIKA — AGRICULTURAL AI

**Category:** AI and Machine Learning  
**Domain:** Agricultural AI, intent classification, RAG, action selection  
**Primary knowledge source:** Package of Practices (Crops)

### Project Overview

KAARSHIKA is an agricultural AI system designed to provide context-aware assistance for agricultural queries. It combines intent classification, information retrieval, reinforcement-learning-based action scoring and selection, and LLM-based response generation.

The system considers the user's query and farm context to identify the relevant intent, retrieve agricultural information, select an appropriate action, and generate a response grounded in the selected information and action.

### System Architecture

User query + farm context → Intent classification → DPR-based retrieval → FAISS search → Action scoring and selection → Qwen2.5-3B-Instruct → Final response

### Technical Implementation

**Intent classification:** KAARSHIKA uses a DistilBERT-based classifier fine-tuned with Parameter-Efficient Fine-Tuning (PEFT) and LoRA to classify incoming agricultural queries.

**Knowledge retrieval:** The system uses the Package of Practices (Crops) document as its primary agricultural knowledge source. Dense Passage Retrieval (DPR) embeddings and FAISS are used to retrieve relevant information.

**Action scoring:** A DistilBERT-based reward model, trained using PEFT, scores candidate actions in the action-selection pipeline.

**Action selection:** The reinforcement-learning-based component scores candidate actions and selects an action for the response pipeline.

**Response generation:** Qwen2.5-3B-Instruct generates the final response using custom prompts and the information provided by the preceding pipeline stages.

**Action preservation:** The selected action is an important control signal. The generation stage is designed to communicate and elaborate on the selected action rather than independently replacing it with a different action.

### Tanmay's Contribution

Tanmay worked on the AI pipeline, including intent classification, document retrieval, action scoring, action selection, and LLM integration.

He implemented the RAG components without relying on LangChain, gaining practical experience with retrieval, vector search, context preparation, and integration with a language model.

### Technologies and Concepts

Python, PyTorch, Hugging Face Transformers, DistilBERT, Qwen2.5-3B-Instruct, PEFT, LoRA, Dense Passage Retrieval (DPR), FAISS, RAG, intent classification, reward scoring, action selection, and prompt engineering.

### What KAARSHIKA Demonstrates

KAARSHIKA demonstrates Tanmay's experience integrating multiple AI components into a structured pipeline. It combines agricultural knowledge retrieval, farm context, intent classification, action selection, and LLM generation in a domain-specific application.

## 4. MIRA — MINE INTELLIGENCE AND RISK ASSESSMENT

**Category:** AI and Machine Learning  
**Domain:** Mine inspection, issue classification, risk assessment, regulatory RAG  
**Regulatory knowledge source:** Coal Mines Regulations (CMR), 2017  
**Development context:** SIH 2026 prototype

### Project Overview

MIRA, or Mine Intelligence and Risk Assessment, is an AI-powered mine inspection and governance prototype. It is designed to assist with inspection finding classification, risk assessment, and retrieval of relevant mining regulations.

The application connects inspection information with AI-based classification, a separate risk assessment engine, regulatory knowledge retrieval, and LLM-generated explanations.

### System Architecture

Inspector application → Flask backend → MariaDB → Inspection and PDF processing → AI classification → Logistic Regression-based risk assessment → Regulatory retrieval → LLM-generated explanation

### Tanmay's Role

Tanmay's responsibility in MIRA focuses on the AI components. Backend development is handled by another team member.

His AI work covers transformer-based classification, risk assessment integration, regulatory retrieval, and LLM integration.

### Classification System

MIRA uses a DistilBERT model fine-tuned with LoRA for classification tasks involving:

- Issue classification
- Category classification
- Severity classification
- Recurrence classification

The classification stage helps structure inspection findings for downstream risk assessment and regulatory analysis.

### Risk Assessment Engine

MIRA uses a Logistic Regression-based risk engine to assess risk.

The risk engine is separate from the classification model and does not use reinforcement learning. This differs from KAARSHIKA, which uses reinforcement-learning-based action scoring and selection.

### Regulatory Retrieval-Augmented Generation

MIRA includes a RAG pipeline based on the CMR 2017 regulations.

The retrieval pipeline uses DPR embeddings and FAISS vector search. Its regulatory knowledge base contains approximately 11,726 chunks.

Retrieved regulatory information provides context to Qwen2.5-3B-Instruct with LoRA, which generates explanations grounded in the retrieved material.

### Technical Implementation

- DistilBERT with LoRA for classification
- Logistic Regression for risk assessment
- DPR embeddings for regulatory information retrieval
- FAISS for vector search
- Approximately 11,726 regulatory knowledge chunks
- CMR 2017 as the regulatory knowledge source
- Qwen2.5-3B-Instruct with LoRA for generation
- English, Hindi, and Hinglish interaction
- Integration of classification, risk assessment, retrieval, and generation
- Local, in-house AI architecture designed without external AI APIs

### Tanmay's Implementation Experience

Tanmay implemented the RAG components without LangChain. This provided hands-on experience with regulatory document retrieval, vector search, retrieved-context integration, and connecting AI components within a larger application.

### What MIRA Demonstrates

MIRA demonstrates Tanmay's experience applying AI techniques to a domain-specific problem. It combines transformer-based classification, conventional machine learning for risk assessment, regulatory RAG, and multilingual LLM generation.

## 5. TIA — CONVERSATIONAL AI PORTFOLIO

**Category:** AI Projects  
**Domain:** Conversational AI, RAG, semantic retrieval  
**Interface:** Gradio

### Project Overview

Tia is Tanmay's personal conversational AI portfolio assistant. It allows recruiters, developers, and other visitors to learn about his background through natural-language conversation.

Tia answers questions about Tanmay's education, technical skills, AI projects, game projects, professional experience, and career interests using a curated knowledge base.

### System Architecture

Professional knowledge-base documents → Text splitting → Sentence-transformer embeddings → ChromaDB → Similarity-based retrieval → Retrieved context + user query → Qwen2.5-3B-Instruct with LoRA → Generated response → Gradio interface

### Technical Implementation

**Knowledge base:** Contains factual information about Tanmay's education, professional profile, AI projects, game projects, technical skills, creative experience, and career interests.

**Text splitting:** Uses RecursiveCharacterTextSplitter to divide documents into smaller chunks suitable for embedding and retrieval.

**Embeddings:** Uses `sentence-transformers/all-MiniLM-L6-v2` to convert text chunks and queries into vector representations.

**Vector database:** Uses ChromaDB to store document chunks and their embeddings for semantic similarity search.

**Retrieval:** Retrieves the most relevant knowledge-base chunks for each user query. The current baseline configuration uses a retriever with `k=4`.

**Language model:** Uses Qwen2.5-3B-Instruct with LoRA for response generation.

**Interface:** Uses Gradio to provide a conversational web interface.

**Grounded generation:** Tia is designed to answer professional questions using retrieved information and to avoid inventing facts about Tanmay.

### Scope and Limitations

Tia focuses on Tanmay's professional background, education, projects, skills, and experience. It is not intended to act as a general-purpose assistant.

Its response quality depends on the accuracy and organization of the knowledge base, retrieval relevance, the quality of the supplied context, and the language model's ability to follow instructions.

Tia is being evaluated for retrieval relevance, answer accuracy, context grounding, and appropriate handling of out-of-scope questions.

### What Tia Demonstrates

Tia demonstrates Tanmay's experience building an LLM-powered application using document processing, embeddings, vector search, ChromaDB, RAG, prompt design, and a conversational interface.
