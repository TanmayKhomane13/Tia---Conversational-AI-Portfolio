## 3. KAARSHIKA — AGRICULTURAL AI

### Project Overview

KAARSHIKA is an agricultural AI system designed to provide context-aware assistance for agricultural queries. It uses the user's query and farm context to classify intent, retrieve relevant agricultural information, select an appropriate action, and generate a response.

The primary knowledge source is the Package of Practices (Crops).

### KAARSHIKA System Architecture

KAARSHIKA follows this pipeline:

User query and farm context → Intent classification → DPR-based document retrieval → FAISS vector search → Candidate action scoring → Action selection → Qwen2.5-3B-Instruct response generation.

### KAARSHIKA Intent Classification

KAARSHIKA uses a DistilBERT-based text classifier fine-tuned using Parameter-Efficient Fine-Tuning (PEFT) and Low-Rank Adaptation (LoRA).

The classifier identifies the intent of incoming agricultural queries so the system can select relevant knowledge and downstream processing.

### KAARSHIKA RAG and Knowledge Retrieval

KAARSHIKA uses Retrieval-Augmented Generation (RAG) to retrieve agricultural guidance from the Package of Practices (Crops).

The retrieval pipeline uses Dense Passage Retrieval (DPR) embeddings and FAISS vector search. The retrieved passages provide agricultural context to the downstream response-generation pipeline.

Tanmay implemented the retrieval components without relying on LangChain, gaining practical experience with document retrieval, embeddings, vector indexing, similarity search, context preparation, and LLM integration.

### KAARSHIKA Action Scoring and Selection

KAARSHIKA includes a reinforcement-learning-based action-selection component.

A DistilBERT-based reward model, trained using PEFT, scores candidate actions. The action-selection component uses these scores to select an action for the response pipeline.

This action-selection process is distinct from document retrieval: retrieval finds relevant agricultural knowledge, while action selection determines which candidate action should guide the response.

### KAARSHIKA Response Generation

KAARSHIKA uses Qwen2.5-3B-Instruct to generate the final response using custom prompts and information supplied by preceding pipeline stages.

The selected action is an important control signal. The generation stage is designed to explain and communicate the selected action rather than independently replacing it with a different action.

### Tanmay's Contributions to KAARSHIKA

Tanmay worked on the AI pipeline, including intent classification, DPR-based retrieval, FAISS search, action scoring, action selection, and LLM integration.

### KAARSHIKA Technologies

Python, PyTorch, Hugging Face Transformers, DistilBERT, Qwen2.5-3B-Instruct, PEFT, LoRA, DPR, FAISS, RAG, intent classification, reward scoring, action selection, and prompt engineering.

### What KAARSHIKA Demonstrates

KAARSHIKA demonstrates Tanmay's experience combining machine learning, domain-specific retrieval, reinforcement-learning-based action selection, and language-model generation in an agricultural AI application.

## 4. MIRA — MINE INTELLIGENCE AND RISK ASSESSMENT

### Project Overview

MIRA, or Mine Intelligence and Risk Assessment, is an AI-powered mine inspection and governance prototype developed in the context of SIH 2026.

The system is designed to assist with inspection finding classification, risk assessment, and retrieval of relevant mining regulations.

Its regulatory knowledge source is the Coal Mines Regulations (CMR), 2017.

### MIRA System Architecture

MIRA integrates inspection information, AI classification, risk assessment, regulatory retrieval, and LLM-generated explanations.

The overall application architecture includes:

Inspector application → Flask backend → MariaDB → Inspection and PDF processing → AI classification → Logistic Regression-based risk assessment → Regulatory retrieval → LLM-generated explanation.

Tanmay's responsibility focuses on the AI components. Backend development is handled by another team member.

### MIRA Inspection Finding Classification

MIRA uses a DistilBERT model fine-tuned with LoRA for classifying mine inspection findings.

The classification tasks include:

- Issue classification
- Category classification
- Severity classification
- Recurrence classification

The classification model structures inspection findings for downstream risk assessment and regulatory analysis.

### MIRA Risk Assessment

MIRA uses a Logistic Regression-based risk engine.

The risk assessment engine is separate from the DistilBERT classification model. It also differs from KAARSHIKA's reinforcement-learning-based action-selection component.

MIRA uses conventional machine learning through Logistic Regression for risk assessment; it does not use reinforcement learning for this component.

### MIRA Regulatory RAG

MIRA uses Retrieval-Augmented Generation to retrieve relevant provisions from the Coal Mines Regulations (CMR), 2017.

Its custom retrieval pipeline uses Dense Passage Retrieval (DPR) embeddings and FAISS vector search.

The regulatory knowledge base contains approximately 11,726 chunks.

Retrieved regulatory passages provide context to Qwen2.5-3B-Instruct with LoRA, which generates explanations grounded in the retrieved material.

### Tanmay's RAG Implementation in MIRA

Tanmay implemented the RAG components without LangChain.

His work provided practical experience with regulatory document processing, passage retrieval, DPR embeddings, FAISS indexing, vector search, retrieved-context preparation, and language-model integration.

### MIRA Language Support and Deployment Approach

MIRA supports interaction in English, Hindi, and Hinglish.

The prototype uses a local, in-house AI architecture designed to operate without external AI APIs.

## 5. TIA — CONVERSATIONAL AI PORTFOLIO

### Project Overview

Tia is Tanmay's personal conversational AI portfolio assistant. It enables recruiters, developers, and visitors to ask natural-language questions about Tanmay's education, professional background, technical skills, AI projects, game projects, and career interests.

Tia is a portfolio-focused conversational application rather than a general-purpose assistant.

### Tia System Architecture

Tia uses the following pipeline:

Professional knowledge base → Document loading → Text splitting → Sentence-transformer embeddings → ChromaDB vector storage → Semantic retrieval → Retrieved context and user query → Qwen2.5-3B-Instruct with LoRA → Generated answer → Gradio interface.

### Tia Knowledge Base

Tia's knowledge base contains information about Tanmay's professional profile, education, projects, technical contributions, skills, publishing experience, creative work, and career interests.

The knowledge base is the factual source for answering questions about Tanmay.

The accuracy and organization of the knowledge base directly affect whether Tia can answer specific questions correctly.

### Tia Document Processing and Chunking

Tia uses LangChain's document-processing components to load and split knowledge-base documents.

RecursiveCharacterTextSplitter was used in the initial pipeline with a chunk size of 500 characters and an overlap of 50 characters.

The knowledge base is also being evaluated with section-based splitting to preserve relationships between project names, headings, and technical details.

Section-based splitting should keep related facts together while oversized sections may require further splitting.

### Tia Embeddings and Vector Storage

Tia uses the sentence-transformers/all-MiniLM-L6-v2 embedding model to convert document chunks and queries into vector representations.

ChromaDB stores the document chunks, embeddings, and metadata for semantic retrieval.

LangChain's HuggingFaceEmbeddings integration and Chroma integration are used in the pipeline.

### Tia Retrieval

Tia retrieves knowledge-base chunks relevant to a user's query.

The baseline retriever configuration uses k=4, meaning it returns up to four retrieved documents.

Tia has also been tested with maximal marginal relevance (MMR) retrieval, which balances query relevance with diversity among selected results.

Retrieval quality depends on the knowledge-base structure, chunk boundaries, embedding model, query wording, retriever configuration, and the relevance of candidate documents.

### Tia Response Generation

Tia uses Qwen2.5-3B-Instruct with LoRA to generate conversational responses.

The model receives the user query and retrieved knowledge-base context.

Tia is intended to answer from the supplied context, combine relevant facts when appropriate, and avoid inventing unsupported information.

If relevant information is present in the retrieved context, the model should use it rather than incorrectly claiming that the information is unavailable.

If the knowledge base does not contain an answer, Tia should acknowledge the limitation rather than fabricate details.

### Tia Interface

Tia uses Gradio to provide a conversational web interface.

The interface allows visitors to ask questions about Tanmay's experience and receive generated answers based on retrieved knowledge.

### Tia Evaluation and Limitations

Tia is being evaluated for retrieval relevance, answer accuracy, context grounding, and appropriate handling of questions outside its scope.

Observed retrieval problems include retrieving general profile information when a query asks about a specific project, returning overlapping chunks, and retrieving information about the wrong project.

These issues may result from knowledge-base organization, chunking, embeddings, retrieval selection, context construction, or generation. They should be investigated separately rather than attributed to a single component without testing.

### Tanmay's Contributions to Tia

Tanmay is developing the knowledge base, document-processing pipeline, embedding and retrieval workflow, ChromaDB integration, prompt design, and conversational application.

### Tia Technologies

Python, LangChain, Hugging Face Transformers, HuggingFaceEmbeddings, sentence-transformers/all-MiniLM-L6-v2, ChromaDB, Qwen2.5-3B-Instruct, LoRA, RAG, prompt engineering, and Gradio.

### What Tia Demonstrates

Tia demonstrates Tanmay's experience building a conversational portfolio application using semantic search, document retrieval, vector storage, LLM generation, and a web interface.
